# 「」で挙げた自著名の補助抜き出し（2026-09-19）

## なぜ要ったか

`rubric.yaml` の抜き出しの対象は「出典行の書名」と「本文の『』の書名」だけだった。そのため一次採点（`../scores.jsonl`）は、回答が「」で挙げた自分の著作名を拾っていない。架空引用率を数えるには、この漏れを埋める必要があった。条件の対応表（`../key.jsonl`）は、この作業の間一度も開いていない。

## 手順とファイル

1. **「」の中身を集める**：192 回答の本文から「」の中身を重複なく集め、番号を振った（`kagi-strings.txt`、899 種）。回答の呼び名も前後の文も付けない。
2. **書名になり得るものに印を付ける**：迷うものも含めて多めに拾う方針。
   - `marks-claude.txt`：この会話を見ていない Claude（Sonnet 5）のサブエージェント、51 種。
   - `astra-marks-request.md` → `astra-marks-result.txt`：ChatGPT の GPT-6 Astra（利用者が画面に添付して貼り付け）、72 種。指示はサブエージェントと同文で、出力の形だけ JSON 行にした。`marks-astra.txt` は同じ内容を「番号<TAB>語」に揃えたもの。
   - `marks-suffix.txt`：語尾（論・義・経・疏など）による機械的な拾い上げ、24 種。
   - **抜き打ち検査**：印を付ける前に当方が見つけていた書名 8 件（いろは歌・即身成仏義・吽字義・密教具足之儀・当字解・御請来目録・御遺告・文鏡秘府論）を、印を付ける側に知らせずに照合した。サブエージェントは「密教具足之儀」を落として不合格（単独では採用しない）、Astra は 8/8 で合格。
3. **判定の束を作る**：3 つの印の和集合 73 種について、回答の中の出現箇所と前後 80 字を集めた（`items.jsonl`、`bundle.md`：121 項目、67 回答）。一次採点で同じ回答に抜き出し済みの書名は除いた。束に条件をにおわせる語が無いことを機械で確かめた。
4. **判定**：各項目が書名か（is_title）、回答が自分の作として挙げたか（as_own）。
   - `result-claude.txt`：この会話を見ていない Claude（Opus 5）のサブエージェント。
   - `result-astra.txt`：GPT-6 Astra（新しい会話で束を添付）。
   - 区分（書名でない／他者の作／自分の作）の一致は 114/121＝94.2%。
5. **書名の照合**：一次採点とこの判定で自分の作とされた書名 37 種を、出典つきで区分した（`../titles.yaml`）。

`scripts/` は上の手順で使った使い捨てのスクリプトの写しで、テストは無い（記録として残す）。リポジトリの直下で `python3 <スクリプト>` として動かした（`check_titles_yaml.py` だけは PyYAML が要るので `.venv/bin/python`）。
