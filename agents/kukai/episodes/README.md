# episodes（判断様式の層）

空海が「その場面でどう決めたか」を一件ずつ記した自作文書。引き継ぎ書 §3.2 の三層構成のうち「判断様式」に当たる。

- ここから抽出した判断原則 5〜10 項目を `../principles.md` に置き、**それだけを常時層（システムプロンプト）に載せる**。episodes 本体は常時層に入れない（1 件 400〜600 字 × 8 件で予算 5,000 トークンを圧迫するため）。
- Phase 4 で Knowledge に投入するかは、そのとき決める。投入する場合も `holdout/` は除く。

## ホールドアウト（2026-09-20 に解放した）

**0001 福州・0005 高野山の伏せは、2026-09-20 に利用者の判断で解いた**（`docs/specs/2026-09-20-phase5-design.md`「方針」1）。実用上その 2 件に答えられないのは不自然であり、ホールドアウトの数値はもともと参考値として結論に使わない扱いだったため。解放後は、評価の H01・H02 を成績として扱わず、集計の報告に「答えを渡した後の問い」と明示する。`holdout/` に残る 0006 は根拠不足で使わない episode で、H01・H02 の出どころではない。

解放前の決め（Phase 2〜4）は次のとおりで、Phase 3・4 の測定はこの条件で取った。伏せた件の判断が原則として常時層に漏れると、ホールドアウト試験は「覚えているか」を測るだけの試験になり無効化するため、執筆の順序を「伏せる件を先に決める → 残りから principles を抽出する」とし、principles.md の抽出元からも外していた。principles.md は解放後も作り直さない（Phase 3・4 の常時層と揃えるため）。

## 書式

frontmatter に事実の出典と信頼区分を、本文に「状況・判断・根拠・検証が要る点」を書く。

```yaml
---
id: ep-kukai-0002          # ep-<agent>-<連番4桁>
title: 恵果からの伝法と早期の帰国
year: 805                  # 出来事の年。幅があるときは開始年
holdout: false             # true なら holdout/ に置く
principle: 授かった法は、身の安全より先に世へ渡す   # principles.md への抽出候補（1 行）
fact_reliability: primary_text   # 下の「事実の区分」から選ぶ
sources:                   # 事実の出所。書名と、そこに何が書かれているか
  - 『御請来目録』（空海自身の上表。請来した経典・法具の一覧と帰国の経緯）
confirmed:                 # 裏が取れた点。何で確かめたかを必ず添える（省略可）
  - 灌頂の次第。出典：東寺公式サイト
verify:                    # まだ裏が取れていない点。数字・人名・書名を具体的に
  - 灌頂の月次
---
```

### 事実の区分（`fact_reliability`）

`knowledge/_schema/metadata.yaml` の `reliability` と同じ語を使う。episode の**地の文は自作**だが、そこに書く事実がどこまで遡れるかを示す。

| 値 | この episode での意味 |
|---|---|
| `primary_text` | 空海自身の著作・書簡に記述がある |
| `academic_research` | 同時代の史書・公文書、または研究で定説とされる |
| `later_attribution` | 後世の伝記・伝承にしかない。**判断の根拠にしてよいが、本人の言葉として引用させない** |

一つの episode に区分の違う事実が混ざるときは、最も弱い区分を frontmatter に書き、強い事実には本文で個別に出典を添える。

## 検証の手順

執筆者（AI）は事実を確定できない。frontmatter の `verify` に挙げた点を確かめ、裏が取れたものを `confirmed` に出典つきで移す。

**抽出の条件は「`verify` が空になること」ではない。** 判断そのものの土台が揺らぐ項目だけを潰せばよく、巻数や日付の細部は未確認のまま先へ進む。引き継ぎ書は「空海AIの完成度は追わない」と定めており、細部の追い込みはこの計画の目的ではない。土台が揺らぐ例：0006 は代筆の書簡の存在自体が未確認のため使わない。

`confirmed` に書くときは、何で確かめたかを必ず添える。例：

```yaml
confirmed:
  - 灌頂の次第（六月に胎蔵、七月に金剛界、八月に伝法阿闍梨位）。出典：東寺公式サイト
```

### 当たる順序（0007 で実際に効いた順）

1. **学術論文を先に探す。** 大学リポジトリ（`*.repo.nii.ac.jp`）、J-STAGE、CiNii。一般の解説記事より先にこちらを見る。0007 では愛媛大学リポジトリの寺内浩「弘法大師空海と満濃池修築」（2019）が決め手になった。
2. **論文が引く一次資料の書名・巻・条を控える。** 論文は結論だけでなく典拠を示す。0007 では『日本紀略』弘仁一二年五月壬戌条に行き着いた。
3. **同時代に近い史料が「何を書いていないか」を見る。** 0007 では 1020 年の「万農池後碑文」に空海の名が無いことが、通説を疑う根拠になった。
4. **一般の解説・自治体サイト・百科事典は最後に、食い違いの検出だけに使う。** 一致すれば補強、食い違えば `verify` に残す。0007 では讃岐国司の名（清原夏野）が論文に現れず、本文から人名を落とした。
5. **AI の記憶は出典にしない。** 執筆時に挙げた書名は当て推量を含む。0007 の初稿で『類聚三代格』を典拠として挙げたが誤りで、正しくは『日本紀略』であった。

### 落とし穴（実際に踏んだもの）

- **文字化けした PDF を「読めたつもり」で引用しない。** 0007 の検証で、抽出に失敗した本文を模様から読み取ったつもりになり、先行研究者の名を取り違えかけた（正しくは亀田隆之）。抽出できたかは、文字コード（実際のコードポイント）で確かめる。
- **広く流布した筋ほど疑う。** 「空海が土木技術で満濃池を修築した」は自治体サイトにも載るが、研究の結論は「常駐して陣頭指揮を執ったのではない」であった。
